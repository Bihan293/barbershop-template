# Барбершоп — шаблон: сайт + Telegram-бот

Готовый шаблон для небольшого барбершопа: премиальный одностраничный сайт,
Telegram-бот с админкой, онлайн-запись, мастера и графики, клиентская база,
фото, согласие с политикой и метрики нагрузки.

Проект можно запускать на Termux, обычном сервере или Railway. База — SQLite
или PostgreSQL/Neon через `DATABASE_URL`. Фото всегда лежат файлами в `media/`,
а в базе хранятся только пути к ним.

Демо-бренд «ЛЕЗВИЕ» и контакты меняются в админке или через `.env`.

## Быстрый старт на Termux

```bash
pkg update && pkg install python -y

cp -r /sdcard/Download/barbershop-template ~/barbershop-template
cd ~/barbershop-template

pip install -r requirements.txt
cp .env.example .env
nano .env          # если nano нет: pkg install nano
```

В `.env` минимум:

- `BOT_TOKEN` — токен из [@BotFather](https://t.me/BotFather);
- `ADMIN_IDS` — ваш Telegram ID (узнать: `/id` в боте).

Запуск:

```bash
python main.py
# или
bash start.sh
```

Сайт: `http://127.0.0.1:8080`. Бот: `/start`, затем `/admin`.

Если не ставится aiohttp:

```bash
pkg install clang libffi openssl -y
pip install --no-cache-dir aiohttp
pip install -r requirements.txt
```

`asyncpg` нужен только для `DATABASE_URL` (Neon) и вынесен в
`requirements-postgres.txt`. Для SQLite он не требуется. На Termux для Neon
может понадобиться `pkg install clang`, после чего:

```bash
pip install -r requirements-postgres.txt
```

## Режимы запуска

```bash
python main.py              # Telegram + сайт + API
python main.py --api-only   # только сайт и API, без Telegram
python main.py --port 8081  # другой порт
```

`--api-only` удобен, чтобы проверить сайт без токена. Заявки сохраняются,
уведомления в Telegram не отправляются (пишутся в лог).

## База данных: SQLite, PostgreSQL, Neon

### SQLite (по умолчанию)

```env
DB_PATH=data/barbershop.db
MEDIA_DIR=media
```

Ничего дополнительно ставить не нужно. Подходит для одного салона на Termux,
Railway с volume или небольшом VPS.

### PostgreSQL / Neon

1. Создайте проект в [Neon](https://neon.tech) и скопируйте connection string.
2. Установите драйвер PostgreSQL:

```bash
pip install -r requirements-postgres.txt
```

3. Добавьте в `.env`:

```env
DATABASE_URL=postgresql://user:password@host/db?sslmode=require
```

4. Перезапустите приложение. Схема создастся автоматически.
5. Фото остаются в `media/` — на Railway это volume, на VPS обычная папка.

Поддерживаются строки Neon с `channel_binding=require` — лишний параметр
автоматически убирается. Для pooler-подключений отключён кэш prepared statements,
поэтому Neon/PgBouncer работает корректно.

Если `DATABASE_URL` пуст — используется SQLite. Если задан — SQLite не нужен,
но `DB_PATH` можно оставить для логов.

Для Neon: бот проверяет напоминания раз в 30 минут, а пул соединений не держит
постоянную сессию. Поэтому при простое compute уходит в scale-to-zero и не
расходует CU-часы. Напоминание всё равно приходит до визита: эффективный анонс —
не меньше 35 минут.

### Перенос существующих данных в Neon

Остановите приложение, затем:

```bash
DATABASE_URL='postgresql://...' \
python scripts/migrate_sqlite_to_postgres.py --source data/barbershop.db
```

Скрипт переносит услуги, мастеров, графики, выходные, заказы, отзывы, галерею,
настройки и служебные ключи. Фото не копируются: перенесите папку `media/`
отдельно. Если в PostgreSQL уже есть заказы, скрипт остановится. Флаг `--force`
очищает целевые таблицы и переносит данные заново — используйте только осознанно.

### Фото и база

- Фото — файлы в `media/services`, `media/gallery`, `media/masters`.
- В базе — только относительный путь (`services/abc.jpg`).
- При замене или удалении фото файл удаляется сразу.
- При старте и по кнопке «🧹 Фото» удаляются файлы-сироты старше 24 часов.

## Что умеет админка

В боте: `/admin`.

- **Заказы** — новые, актуальные, «сегодня», все. Карточка содержит имя, телефон,
  услугу, мастера, цену, дату, время, канал связи и комментарий. Статусы:
  подтверждён, отменён, завершён. Все изменения — с подтверждением.
- **➕ Новая запись** — ручная запись клиента админом: имя, телефон, одна или
  несколько услуг, мастер, дата, время и комментарий. Можно сразу создать как
  новую или подтверждённую. Согласие клиента фиксируется в заказе.
- **Мастера** — имя, описание, фото, включение/отключение, график на неделю,
  несколько перерывов/обедов на день, постоянные выходные по дням недели,
  разовые выходные и отпуск, «сегодня выходной». Полный CRUD.
- **Услуги** — название, описание, цена, длительность, фото. Добавить, изменить,
  удалить.
- **Галерея** — фото с подписью, замена, удаление.
- **Отзывы** — имя, текст, рейтинг 1–5, источник.
- **Почему мы** — эмодзи, заголовок, текст.
- **Контакты** — адрес, часы, телефон, WhatsApp, 2ГИС, Instagram, имя заведения,
  город.
- **Настройки** — онлайн-запись, шаг слотов, часы по умолчанию, общий предел
  старта, напоминание админу.
- **Фото** — статистика по папкам, проверка сирот и очистка.
- **Нагрузка** — запросы, ошибки, p50/p95, посетители, размер БД и медиа,
  память процесса, а также количество заявок из базы (не сбрасывается при
  перезапуске).
- **Цифры и достижения** — блок под обложкой сайта. Можно менять значения и
  подписи, ставить плюсик, добавлять и удалять свои достижения: число или
  короткий текст, например «50 точек по всему миру» или «Знаменитости ·
  стригутся у нас». Текущие три цифры сохраняются при обновлении.

Данные сайта загружаются при открытии или обновлении страницы. Фоновых запросов
к базе нет — это снижает нагрузку и позволяет Neon уходить в scale-to-zero.
Бот и сайт работают с одной базой.

### Мастера и график

У каждого мастера свой календарь. Это значит:

- два мастера могут принимать разных клиентов на одно и то же время;
- клиент выбирает конкретного мастера или «любой свободный»;
- если выбран «любой», сервер сам назначит свободного мастера;
- у каждого дня недели свои часы, несколько перерывов/обедов и признак
  «рабочий/выходной»;
- «Выходные по дням» — постоянные: например, суббота выходная каждую неделю;
- можно отметить конкретную дату как разовый выходной или отпуск;
- отключённый мастер исчезает с сайта и из записи, но его старые заказы остаются;
- если мастер отключается, берёт выходной или у него выключается день недели,
  Telegram-клиенты получают сообщение, а админ — список затронутых записей
  с телефонами. Клиенты с сайта видят плашку и предупреждение в «Моих записях»,
  и админ связывается с ними вручную.

По умолчанию создаётся мастер **Михаил** с графиком пн–вс 10:00–21:00 и обедом
14:00–15:00. Его можно переименовать, отключить или удалить, а также добавить
других. Постоянные выходные и перерывы сохраняются в базе и переживают
перезапуск.

## Клиентская запись

Клиент в боте:

1. `/menu` → «Записаться»;
2. услуга → мастер (или «любой свободный») → дата → время;
3. имя → телефон (можно отправить контактом) → Telegram/WhatsApp → комментарий;
4. проверка, согласие с политикой и подтверждение.

Заявка сразу приходит всем администраторам. Если клиент выбрал WhatsApp, в
подтверждении будет кнопка открыть чат.

Сайт:

- имя, телефон, услуга, **мастер**, дата, время, канал связи, комментарий;
- галочка согласия с политикой — без неё кнопка не отправляет форму;
- свободные слоты учитывают мастера, график, обед, выходные и длительность услуги;
- повторная запись на занятое время блокируется;
- после успеха показывается номер заявки и мастер;
- если API недоступен, форма предлагает отправить заявку в WhatsApp.

В боте в «Мои записи» клиент может сам отменить или перенести будущую запись.
Старый слот сразу освобождается, новый блокируется, администратор получает
уведомление с телефоном и деталями.

На сайте есть раздел **«Мои записи»**. После записи в браузере сохраняется
защищённый токен, поэтому на этом устройстве клиент видит услугу, мастера,
дату, время и стоимость, может отменить или перенести запись. На другом
устройстве записей не будет — там нужно позвонить в салон. Это сделано
специально, чтобы записи не открывались по одному номеру телефона.

Если мастер стал недоступен, клиент с сайта увидит плашку «Есть изменения
в вашей записи» при следующем открытии сайта и предупреждение в «Моих записях».

Защита от спама: лимит заявок с одного IP, honeypot-поле и серверная валидация.

### Слоты и длительность

Слоты считаются по полной длительности услуги:

| Услуга | Занято | Следующий свободный старт |
|---|---|---|
| 30 мин, старт 17:00 | 17:00–17:30 | 17:30 |
| 60 мин, старт 17:00 | 17:00–18:00 | 18:00 |
| 120 мин, старт 17:00 | 17:00–19:00 | 19:00 |
| 180 мин, старт 17:00 | 17:00–20:00 | зависит от закрытия |

Перерывы (их может быть несколько) блокируют старты, которые пересекаются с
ними. Постоянный выходной по дню недели, разовый выходной и отключённый мастер
не дают слотов. Общий предел старта (`last_slot`) действует для всех мастеров;
часы каждого дня задаются в графике мастера.

Если сегодня уже прошло утро, сайт и бот показывают только оставшиеся слоты и
пишут, с какого времени доступна запись. На другую дату показывается полный день
по графику мастера.

### Отмена и перенос

- Клиент из Telegram получает уведомление об отмене/переносе автоматически.
- Клиент с сайта — нет: админ видит телефон и подсказку «сообщите клиенту»,
  плюс кнопку WhatsApp.
- При переносе старый слот сразу освобождается, новый блокируется на полную
  длительность. Перенос идёт к тому же мастеру; если он отключён — к свободному.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/site` | услуги, мастера, галерея, отзывы, «Почему мы», контакты |
| GET | `/api/slots?date=YYYY-MM-DD&service_ids=1,2&master_id=1` | свободное время |
| POST | `/api/bookings` | создать заявку |
| POST | `/api/my-bookings` | записи по токенам браузера |
| POST | `/api/my-bookings/cancel` | отменить запись |
| POST | `/api/my-bookings/slots` | свободное время для переноса |
| POST | `/api/my-bookings/reschedule` | перенести запись |
| GET | `/api/health` | состояние сервера и БД |
| GET | `/api/metrics?token=...` | метрики нагрузки |
| GET | `/` | сайт |
| GET | `/privacy.html` | политика обработки данных |
| GET | `/media/...` | фото |

`master_id` необязателен: без него API вернёт объединение слотов всех активных
мастеров. `service_ids` — список услуг: длительность и цена суммируются, слоты
проверяются на общую длительность. Старые поля `service_id`/`service` тоже
поддерживаются для совместимости.

`POST /api/bookings`:

```json
{
  "name": "Аскар",
  "phone": "+7 701 234 56 78",
  "service_ids": [1, 2],
  "services": ["Стрижка", "Борода"],
  "master_id": 1,
  "consent": true,
  "date": "2026-11-15",
  "time": "14:30",
  "channel": "whatsapp",
  "comment": "Пожелания",
  "company": ""
}
```

`consent: true` обязателен для сайта. Сервер сохраняет дату и время согласия в
заказе. Для записей из Telegram согласие фиксируется при нажатии
«Подтвердить запись». В ответе сайт получает `access_token` — по нему браузер
показывает запись в разделе «Мои записи».

## Согласие и политика

- На сайте под формой есть галочка и ссылка на `/privacy.html`. Без галочки
  кнопка «Записаться» неактивна.
- В Telegram перед подтверждением показывается текст согласия и ссылка на
  политику (если задан `PUBLIC_URL` или `SITE_URL`).
- `site/privacy.html` — шаблон политики. Подставьте юридически проверенный текст
  для конкретного салона. Бренд, город, адрес, телефон и дата редакции
  подставляются из настроек автоматически.
- Дата согласия хранится в `orders.consent_at`.

## Метрики и нагрузка

`/api/metrics` отдаёт JSON, `/stats` в боте — краткую сводку для админа.

Что считается:

- количество запросов, ошибок 5xx, распределение по статусам и путям;
- p50/p95/max времени ответа;
- уникальные посетители за день (в памяти, без записи IP в лог);
- заявки с сайта и из Telegram;
- количество заказов, мастеров, услуг;
- размер БД, медиа, свободное место;
- RAM процесса.

Доступ к `/api/metrics`:

- если задан `METRICS_TOKEN`, нужен `?token=...`;
- если токен не задан, доступ только с localhost.

Для одного салона с 7–10 клиентами в день нагрузка минимальна. Узкое место —
SQLite (один писатель). Для нескольких салонов/реплик используйте PostgreSQL.

Логи пишутся в `data/bot.log` с ротацией (2 МБ × 3). В лог не попадает токен
бота: логирование `httpx`/`httpcore` отключено.

## Webhook (опционально)

Для Termux достаточно polling — домен не нужен. Для сервера с HTTPS:

```env
PUBLIC_URL=https://barber.example.com
USE_WEBHOOK=true
WEBHOOK_SECRET=длинная-случайная-строка
```

- приложение слушает `0.0.0.0:8080`;
- поставьте HTTPS-прокси (Caddy/Nginx) на этот порт;
- бот сам установит webhook на `/tg/webhook/<secret>`;
- сайт и фото будут отдаваться с `PUBLIC_URL`.

## Railway и Docker

В проекте есть `Dockerfile` и `.dockerignore`. Для Railway:

1. Задеплойте репозиторий как Docker-сервис.
2. Добавьте volume и смонтируйте в `/app/storage`.
3. Переменные:

```env
DATABASE_URL=postgresql://...        # Neon (рекомендуется)
# или SQLite на volume:
DB_PATH=/app/storage/barbershop.db
MEDIA_DIR=/app/storage/media

HOST=0.0.0.0
PUBLIC_URL=https://ваш-домен
SITE_URL=https://ваш-домен
BOT_TOKEN=...
ADMIN_IDS=...
METRICS_TOKEN=...
USE_WEBHOOK=false
```

`PORT` Railway подставляет сам. Реплика — одна, если используете SQLite и
локальные фото. С Neon можно несколько реплик, но фото всё равно должны лежать
в общем хранилище (S3/R2) — для одного салона это не нужно.

Ориентир по стоимости Railway: Hobby $5/мес, обычно $5–8/мес для одного
небольшого сервиса.

## Шаблон для другого салона

Код не нужно переписывать. На каждый салон — свой деплой, бот, домен и база.
Меняются только:

1. `.env` — токен, `ADMIN_IDS`, домен, база.
2. `site/themes/*.css` — тема внешнего вида. В `site/theme.css` поменяйте
   `@import url("themes/dark-gold.css");` на нужную тему. Готовые варианты:
   `dark-gold` и `light-pink`. Подробности — в `site/themes/README.md`.
3. `site/index.html` — статические тексты, которые не редактируются в админке:
   hero, блок «О баре», SEO-мета, JSON-LD, ссылка на Google Fonts.
4. `site/privacy.html` — юридический текст политики и ссылка на шрифты.
5. Контент (услуги, мастера, фото, отзывы, контакты) — через админку бота.

Чтобы сделать новый стиль, скопируйте `site/themes/dark-gold.css` в
`site/themes/my-theme.css`, поменяйте переменные и подключите этот файл в
`site/theme.css`. Внутренний код приложения менять не нужно.

Фото должны лежать в `media/`; база хранит только пути. При переносе на другой
сервер скопируйте `media/`, иначе фото не появятся.

## Данные и бэкапы

- SQLite: `data/barbershop.db`.
- PostgreSQL/Neon: данные на стороне провайдера.
- Фото: `media/`.

Отдельный автоматический бэкап в проекте не настроен. По решению для этого
продукта база в Neon считается ответственностью провайдера, а потерей фото
можно пренебречь. Если нужен бэкап фото — скопируйте `media/` в S3/R2 или на
другой диск. Для SQLite можно периодически копировать `data/` при остановленном приложении (или вместе с `-wal`/`-shm`).

---

## Безопасность

- Не публикуйте `.env` и токен бота.
- `ADMIN_IDS` ограничивает доступ к админке.
- API имеет rate limit, honeypot и серверную валидацию.
- Для продакшена используйте HTTPS.
- Токен, попавший в лог, считается скомпрометированным: @BotFather → `/revoke`.

## Возможные проблемы

**Бот не отвечает.** Проверьте `BOT_TOKEN`, интернет и лог. Токен — без кавычек.

**Нет доступа к админке.** `/id`, добавьте ID в `ADMIN_IDS`, перезапустите.

**Порт занят.** `python main.py --port 8081`.

**Сайт без API.** Остаётся статичная версия, запись предлагает WhatsApp.

**Фото не видно.** Убедитесь, что запущен `main.py` (он раздаёт `/media`), и
обновите страницу.

**Neon не подключается.** Проверьте `DATABASE_URL`, `sslmode=require`, доступ к
проекту и что не исчерпан лимит. Ошибка `asyncpg` при старте означает, что база
недоступна или неверны логин/пароль.

**После переноса в Neon нет фото.** Фото не в базе: скопируйте `media/` на новый
сервер/volume.
